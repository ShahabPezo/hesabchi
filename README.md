حسابچی

**حسابچی** یک اپلیکیشن اندرویدی فارسی، راست‌به‌چپ و آفلاین برای مشاهده اطلاعات مشتریان، فاکتورها، مانده‌حساب‌ها و قیمت‌های به‌روز است. داده فقط با واردکردن یک فایل JSON نسخه‌دار از برنامه ویندوزی به‌روزرسانی می‌شود؛ برنامه هیچ سرور، حساب کاربری یا ارسال داده‌ای ندارد.

## خروجی آماده استفاده

فایل نصب نسخه آزمایشی در مسیر زیر قرار دارد:

```text
release/namayeshyar-debug.apk
```

این APK با کلید توسعه امضا شده و برای نصب و آزمون مستقیم روی دستگاه مناسب است. برای انتشار در Google Play یا توزیع رسمی، باید یک کلید اختصاصی انتشار ایجاد و نسخه release را با آن امضا کنید. فرایند ساخت APK آزمایشی و تفاوت آن با نسخه انتشار در راهنمای رسمی Android توضیح داده شده است.[1]

## قابلیت‌های پیاده‌سازی‌شده

| بخش | قابلیت |
|---|---|
| ورود داده | انتخاب فایل `.json` از حافظه، یا ارسال آن از گزینه Share در تلگرام/فایل‌منیجر به اپلیکیشن |
| اعتبارسنجی | بررسی نسخه، ساختار، فیلدهای ضروری، مبلغ‌ها، شناسه‌های تکراری و ارتباط فاکتور با مشتری |
| حفظ داده | نگهداری آخرین ورودی معتبر در پایگاه‌داده محلی SQLite؛ ورود فایل خراب داده قبلی را حذف نمی‌کند |
| صفحه خانه | مجموع مانده قابل وصول، آمار مشتری/فاکتور/کالا و فاکتورهای اخیر |
| مشتری‌ها | جست‌وجوی نام، تلفن یا شناسه؛ مشاهده مانده و فاکتورهای هر مشتری |
| فاکتورها | جست‌وجو، فیلتر وضعیت، مشاهده پرداخت، باقی‌مانده و اقلام هر فاکتور |
| قیمت‌ها | جست‌وجوی نام یا کد کالا، نمایش قیمت و زمان آخرین به‌روزرسانی |
| تنظیمات | تم روشن/تیره/سیستمی، ورود فایل جدید و پاک‌سازی کنترل‌شده داده محلی |
| رابط فارسی | راست‌به‌چپ، تاریخ جلالی، اعداد فارسی و فونت Vazirmatn |

## نصب و استفاده

ابتدا فایل `release/namayeshyar-debug.apk` را به گوشی اندرویدی منتقل و نصب کنید. سپس در صفحه نخست روی **«انتخاب فایل JSON»** بزنید و فایل خروجی را انتخاب کنید. راه دیگر این است که در تلگرام یا فایل‌منیجر، فایل JSON را انتخاب و از گزینه **اشتراک‌گذاری**، «حسابچی» را انتخاب کنید. بعد از ورود موفق، تمام داده‌ها بدون نیاز به اینترنت در برنامه قابل مشاهده‌اند.

> با ورود فایل جدید، اطلاعات قبلی با اطلاعات معتبر تازه جایگزین می‌شود. اگر فایل ناسازگار یا خراب باشد، برنامه علت خطا را فارسی نمایش می‌دهد و اطلاعات قبلی را نگه می‌دارد.

## قرارداد فایل JSON — نسخه ۱

فایل ورودی باید با UTF-8 ذخیره شود و مقدار `version` آن برابر `1` باشد. مبلغ‌ها به‌صورت عدد صحیح **ریالی** و تاریخ‌ها در قالب ISO 8601 ثبت می‌شوند. اپلیکیشن تاریخ‌ها را در رابط کاربری به تقویم جلالی نمایش می‌دهد.

```json
{
  "version": 1,
  "exportedAt": "2026-08-20T10:30:00Z",
  "business": {"name": "نام کسب‌وکار", "currency": "IRR"},
  "customers": [
    {
      "id": "C-1001",
      "name": "شرکت نمونه",
      "phone": "09120000000",
      "balance": 12500000,
      "updatedAt": "2026-08-20T10:00:00Z"
    }
  ],
  "invoices": [
    {
      "id": "INV-1001",
      "customerId": "C-1001",
      "customerName": "شرکت نمونه",
      "issuedAt": "2026-08-18T00:00:00Z",
      "dueAt": "2026-08-25T00:00:00Z",
      "total": 20000000,
      "paid": 7500000,
      "status": "partial",
      "items": [
        {"title": "کالای نمونه", "quantity": 2, "unitPrice": 10000000, "total": 20000000}
      ]
    }
  ],
  "prices": [
    {
      "id": "P-1001",
      "title": "کالای نمونه",
      "sku": "SKU-1001",
      "price": 10000000,
      "updatedAt": "2026-08-20T10:00:00Z"
    }
  ]
}
```

| فیلد | توضیح |
|---|---|
| `version` | الزامی؛ در این نسخه فقط مقدار `1` پذیرفته می‌شود. |
| `exportedAt` | زمان ساخت خروجی در قالب ISO 8601. |
| `business` | نام کسب‌وکار و واحد پول. |
| `customers` | آرایه مشتریان؛ هر شناسه `id` باید یکتا باشد. |
| `invoices` | آرایه فاکتورها؛ `customerId` هر فاکتور باید به یک مشتری موجود اشاره کند. |
| `status` | یکی از `paid`، `partial`، `unpaid` یا `overdue`. |
| `prices` | آرایه کالاها و قیمت‌های به‌روز؛ شناسه `id` هر کالا یکتا است. |

نمونه واقعی و قابل ورود در مسیر `assets/samples/sample_business_data.json` قرار دارد.

## ساخت از کد منبع

پیش‌نیازها Flutter و Android SDK هستند. ابتدا وابستگی‌ها را دریافت کنید و آزمون‌ها را اجرا کنید:

```bash
flutter pub get
flutter analyze
flutter test
```

سپس برای ساخت APK آزمایشی این دستور را اجرا کنید:

```bash
flutter build apk --debug
```

خروجی در `build/app/outputs/flutter-apk/app-debug.apk` ایجاد می‌شود. Android SDK برای ساخت به ابزارهای command-line، platform و build tools نیاز دارد.[2]

## دامنه نسخه فعلی و گام بعدی

این تحویل، **اپلیکیشن نمایشگر اندروید** است و به‌صورت مستقیم فایل `cardboard.db` را نمی‌خواند. گام بعدی در برنامه ویندوزی باید یک ماژول یا اسکریپت جداگانه باشد که داده‌های موردنیاز را هر چند دقیقه از `cardboard.db` به همین قرارداد JSON صادر کند. پس از آن فایل JSON از راه پیام‌رسان، حافظه گوشی یا یک سرویس همگام‌سازی جداگانه به کارفرما می‌رسد.

> چون داده‌های مالی فقط در دستگاه ذخیره می‌شوند، پاک‌سازی داده از تنظیمات صرفاً نسخه محلی برنامه را حذف می‌کند و فایل JSON اصلی شما را تغییر نمی‌دهد.
